# src/gl/ — WebGL API Surface (WebGL1 + WebGL2 contexts)

## Intent
The complete WebGL 1.0 (`WebGLRenderingContext`) and WebGL 2.0 (`WebGL2RenderingContext`) API surface of the software renderer: all GL state, all WebGL object classes, the error queue, per-call validation, attribute fetch + vertex evaluation, draw-call assembly into the rasterizer, texture/FBO management, readPixels/clear/blit, context lifecycle, and the extension registry. Pure TS, zero runtime deps. Consumes `glsl/` (shader compile/link — contract §1 in `../CONTEXT.md`), `raster/` (DrawCall, formats, sampler, surfaces — contracts §2/§3), `present/` (canvas surfaces, image decode — contract §4). Those modules' `index.ts` files carry the full types; gl/ compiles against them.

**Phase status: Phase 2 COMPLETE + wave-5 conformance2 API-core COMPLETE.** All `api/` mixins, engine modules, object classes, and extension factories are implemented and wired. `installAll` is invoked at the bottoms of `webgl1.ts`/`webgl2.ts`. `npx tsc --noEmit` clean; unit tests 115/115.

## API Surface
- `index.ts` — barrel: exports both context classes, constants (`C1`, `C2`, `CExt`, `C`), all object classes, state model, errors, validation, engine entry points, extension registry + types, `installAll`.
- `webgl1.ts` — `class WebGLRenderingContext` with EVERY WebGL1 method declared (exact spec signatures; arity matters — CTS checks `function.length`). `canvas`/`drawingBufferWidth`/`drawingBufferHeight` are prototype getters. `CONTEXT_TOKEN: unique symbol` gates construction (only `lifecycle.ts` may construct). Bottom: `installConstants(proto, C1)` + `installAll(proto)` + `chainToNative(proto, 'WebGLRenderingContext')` + `makePrototypeMethodsNonEnumerable` (offscreencanvas/methods-2: WebIDL methods must not be enumerable).
- `webgl2.ts` — `class WebGL2RenderingContext extends WebGLRenderingContext` (constructor `super()` + typing; in NODE the prototype chain also makes `instanceof WebGLRenderingContext` true) with all WebGL2 additions incl. `copyBufferSubData`, `drawingBufferStorage`, `releaseShaderCompiler`. Bottom: `installConstants(proto, C1)` + `installConstants(proto, C2)` (full constant surface as OWN props — required once the prototype is re-chained), `installAll(proto)` (idempotent; entry.ts also calls), copies the 3 class-body getters from the WebGL1 prototype, then `chainToNative(proto, 'WebGL2RenderingContext')` (REPLACES the class-extends prototype link with the native WebGL2 link in browsers) + `makePrototypeMethodsNonEnumerable`.
- `native-chain.ts` — `chainToNative(ourProto, nativeGlobalName)`: re-chains a class prototype under the native browser class of the same name (browser only; guarded no-op in Node). PROTOTYPE-ONLY — never touches constructor `[[Prototype]]` (that would redirect `super()` to the illegal native constructor). See "Native instanceof chaining" design note below.
- `constants.ts` — `C1` (WebGL1 GLenum values), `C2` (WebGL2 values), `CExt` (extension constants incl. compressed formats, timer query, norm16, clip/cull, draw-buffers), merged `C` for engine use, `installConstants(proto, table)` (enumerable, non-writable). NOTE: C1/C2 are exactly the constants installed on the context prototypes — CTS `constants-and-properties*.html` enumerate `for (var i in gl)` and fail on ANY extra non-function property. Values removed from the WebGL spec or added post-CTS-suite live in `CInternal` (merged into `C`, never installed). NOTE: constants.ts follows the Khronos **WebGL** convention where NEAREST_MIPMAP_LINEAR=0x2702 / LINEAR_MIPMAP_NEAREST=0x2701 (swapped vs OpenGL ES) — the raster sampler MUST interpret raw filter values per this same convention.
- `state.ts` — `State` interface + `createDefaultState(version: 1|2)` (+ alias `createState`) with spec defaults; `Limits`/`defaultLimits()`; per-attrib/VAO/Blend/Stencil/PixelStore state. Plain mutable data, no logic.
- `errors.ts` — `ErrorQueue` (push/get/peek/hasErrors/clear; cap 256, spec ordering).
- `validation.ts` — `validateObject` (TypeError for non-WebGLObject; INVALID_OPERATION + null for cross-context/deleted), numeric/enum/string guards.
- `objects/` — one file per class: WebGLObject (abstract base: `_context` tag, `_deleted`), WebGLBuffer (`_target`, `_data`, `_size`, `_usage`, `_deletePending`, `_tfRangeBindings`), WebGLTexture (`_levels[faceIndex][level]`, `_params` — spec defaults incl. MIN_FILTER=NEAREST_MIPMAP_LINEAR(0x2702), MAX_LEVEL=1000, MIN/MAX_LOD=∓1000, MAX_ANISO=1; `_image: GLTextureImage|null`, `_deletePending`), WebGLShader (+`_translatedSource`: set on successful compile, '' on failure, null on shaderSource reset — shaderSource KEEPS compile status per spec), WebGLProgram (+`_uniformStore: DataView|null`, `_blockStores`, `_bindAttribLocations`, `_transformFeedbackVaryings`, `_tfBufferMode`, `_linkComplete`), WebGLFramebuffer (`_attachments: Map<GLenum, FramebufferAttachment>`, `_status`, `_multisampled`), WebGLRenderbuffer (`_surface: Surface|null`, `_samples`), WebGLVertexArrayObject (holds VAOState), WebGLSampler, WebGLQuery (`_active`, `_result`, `_resultAvailable`), WebGLSync (`_signaled` — flipped by a one-shot setTimeout(0), event-loop-deferred), WebGLTransformFeedback (per-object indexed buffer bindings `_buffers[i]`/`_bufferRanges[i]`), `aux.ts` (WebGLUniformLocation {_program,_index,_name}, WebGLActiveInfo, WebGLShaderPrecisionFormat), `index.ts` (barrel + `OBJECT_CLASSES` + `Resources` + `createObject` + bottom-of-module `chainToNative` calls for ALL 14 concrete classes).
- `framebuffer-util.ts` — `resolveFramebufferTarget(ctx)` (real: builds the `FramebufferTarget` the rasterizer draws into) + `checkFramebufferStatus` full completeness rules: attachment completeness, format/attachment-point match, W2 color-renderable table (unsized RGBA/RGB and RGB8 texture+renderbuffer → COMPLETE per GLES3 Table 3.13 — rgb-format-support/framebuffer-render-to-layer/invalidate-framebuffer hard-require; integer formats per W2_COLOR_RENDERABLE_CORE), depth/stencil attach mismatch → INVALID_OPERATION at attach time (deferred to completeness when image not yet allocated), draw-buffer count, mip level (GLES3 §4.4.5 base-level rule: attached level ≠ base must lie in [baseLevel, q] with a mipmap-complete chain), multisample mismatch, layer targets. ## Constraints
- Each file ≤ ~1000 lines (mixin pattern exists precisely for this; do NOT grow webgl1.ts/webgl2.ts class bodies beyond signatures — implementations live in api/ modules).
- Zero runtime deps; no DOM in core paths (canvas is abstract via present/).
- GL error semantics: WebIDL conversion failures THROW TypeError (JS conversion per WebGL spec); cross-context/deleted objects → INVALID_OPERATION + no-op; internal exceptions NEVER escape — catch at the API boundary, report via GL errors. Error queue ordering per spec (oldest first, FIFO). WebIDL NaN/Infinity → 0 via `Number(v) >>> 0` (blitframebuffer-test typo `gl.COLOR_ATTACHENT0` must not pageerror).
- No per-fragment allocation in hot paths (draw pipeline uses preallocated typed-array scratch).
- Correct method arity (function.length) and prototype placement: constants + getters on prototype, non-writable.
- All validation must match the WebGL spec: value ranges, buffer offsets/alignment (UNPACK_ALIGNMENT, uniform buffer offset alignment 256), FBO completeness before draw (INVALID_FRAMEBUFFER_OPERATION), program link state, uniform type/size mismatch → INVALID_OPERATION, MAX_* limits consistent with `Limits`/`defaultLimits()`.
- Contract §1 conformance: `compileShader`/`linkProgram` from glsl/; ProgramModel.uniforms[].location is the index into the per-program `_uniformStore` DataView (uniform* calls write there); sampler values validated < MAX_COMBINED_TEXTURE_IMAGE_UNITS; matrix transpose must be false (INVALID_VALUE).
- Contract §2 conformance: vertex records packed `[px,py,pz,pw, pointSize, clipDistance[8], cullDistance[8], varyings...]` per Program.varyings (21-float header: 0-3 position, 4 pointSize, 5-12 clipDistance, 13-20 cullDistance, varyings from offset 21 — local `RECORD_TOTAL_HEADER_FLOATS` in draw.ts; keep in lockstep with raster's `RECORD_HEADER_FLOATS`/`VARYINGS_OFFSET`, see Cross-Agent Contract Notes); DrawCall carries the full state snapshot.
- bindBufferRange/bindBufferBase: offset+size>buffer-size is NOT an error at BIND (deferred to draw, ANGLE issue 3388); the 65536 MAX_UNIFORM_BLOCK_SIZE check applies to the range SIZE not the offset; WebGL2 allows multi-target buffer rebinds.

## Design Decisions
- **Precision model (audited)**: ALL shader-facing storage is fp32 — uniforms (`_uniformStore` DataView over glsl `floatStore: Float32Array`, writes via `setFloat32`; draw.ts:2174-2184), UBO block stores (`new Float32Array(buf._data, ...)` views, draw.ts:2165), vertex attribs (dense Float32Array pool extraction + `constantF: Float32Array`, draw.ts:944/880; FLOAT attribs are bit-exact round trips via `getFloat32`, normalized int attribs are correctly-rounded fp32 since the double division has 53-bit precision), vertex records/varyings (Float32Array), gl_FragCoord (Float32Array, integer+0.5 exact), gl_DepthRange builtin (Float32Array, draw.ts:2198). NO double reaches shader math through storage. The generated shader code itself, however, evaluates in JS IEEE doubles (no per-op `Math.fround`; only lexer literals `src/glsl/lexer.ts:314` and bitcast helpers `src/glsl/codegen/runtime.ts:466/472` fround) — values are fp32-rounded once at the typed-array boundaries. Double-vs-fp32 arithmetic differences are ≤1 ULP (~6e-8 relative) → ≤1 luma after 8-bit encode, insufficient to explain ±1..20 scattered luma deltas vs native. State fields typed as plain JS doubles (clearColor/clearDepth state.ts:270-271, blend.color state.ts:267, depth.range state.ts:268, polygonOffset/sampleCoverage state.ts:287-288) flow into DrawCall as doubles (draw.ts:1370/1407/1420/1429/1448) and are fp32-rounded only at the surface store/encode — ≤1 luma deviation for boundary values (e.g. clearColor(0.1) → 25 vs native 26); exact 0/1 clears/blend colors are unaffected.
- **Why JS codegen for GLSL** (moved from src/CONTEXT.md — kept here for gl-side context): correctness (CTS shader tests) AND performance (three.js/Babylon render scenes with tens of thousands of triangles; an interpreter would be too slow for the visual suites). Compile once at link time; the generated function closes over nothing mutable except the exec context. (CTS-backed where noted)
- **Class hierarchy**: `WebGL2RenderingContext extends WebGLRenderingContext` (constructor `super()` + typing; in NODE the prototype chain also makes `instanceof WebGLRenderingContext` true for WebGL2 contexts). In BROWSERS the prototypes are re-chained under the native classes (see "Native instanceof chaining"); WebGL1 class carries all base methods; WebGL2 adds on top. Interface merging adds typed getExtension overloads.
- **Native instanceof chaining**: the CTS harness checks `ctx instanceof WebGLRenderingContext`/`WebGL2RenderingContext` (and object identity via instanceof) against the NATIVE browser classes (`webgl-test-utils.js` `isWebGLContext`) — a failed check falls back to `gl.getImageData(...)` and breaks rendering tests. `native-chain.ts` `chainToNative` re-chains each of our class prototypes UNDER the native prototype of the same name (browser only; guarded no-op in Node). Mapping: the 2 context classes + all 14 concrete object classes (objects/index.ts bottom). The abstract `WebGLObject` base is NOT chained (only instance fields, no runtime instanceof checks against it). PROTOTYPE-ONLY: constructor `[[Prototype]]`s are untouched (native WebGL constructors are illegal — redirecting `super()` would throw "Illegal constructor"). Consequences in browsers: (a) WebGL2 instances are NO LONGER `instanceof WebGLRenderingContext` — mirrors native Chromium (separate interfaces); (b) instances keep `instanceof OurConcreteClass`, so all internal instanceof checks stay valid; (c) the WebGL2 prototype must own everything it previously inherited through the class-extends chain — hence C1 constants and the `canvas`/`drawingBufferWidth`/`drawingBufferHeight` getters are installed as OWN properties on `WebGL2RenderingContext.prototype` in webgl2.ts.
- **Prototype-mixin implementation**: class declarations own signatures + arity; `api/<group>.ts` replaces stub bodies via assignment.
- **Error/validation model**: TypeError for WebIDL conversion failures; INVALID_* via ErrorQueue; internal exceptions swallowed at API boundary.
- **antialias reporting**: W1 reports `false` (CTS requires real AA pixels for true); W2 reports exactly what was requested. Buffer is single-sampled in both cases.
- **SAMPLE_ALPHA_TO_COVERAGE (plumbed, wave-8)**: the cap was tracked in state (state.ts caps L260/346, getters, api/state.ts) but silently dropped at DrawCall construction; `buildDrawCall` (draw.ts) now sets `sampleAlphaToCoverage: s.caps.SAMPLE_ALPHA_TO_COVERAGE` on the DrawCall. Raster gates fragments on it in `finalize()` (alpha→coverage via the deterministic coverage hash — see src/raster/CONTEXT.md). three.js enables the cap per material (WebGLState.js, `material.alphaToCoverage === true`) — webgl_lines_fat exercises it; no graded CTS test checks A2C behavior (state-query tests only).
- **failIfMajorPerformanceCaveat**: always create the context and report the requested value — no CTS test exercises it; software implementations may return null per spec but creating is safer.
- **Resize semantics** (verified against CTS): realloc + clear (color 0, depth 1.0, stencil 0), viewport/scissor/state preserved, zero-size → 1×1, `drawingBufferWidth/Height` live getters.
- **Context loss** (CTS context-lost PASSES): events dispatched async; `preventDefault()` on the lost event gates restore; resize while lost reallocates nothing but stays lost. While lost: getters return null; ALL void calls are SILENT no-ops; `loseContext()` on an already-lost context → INVALID_OPERATION and `restoreContext()` on a live context → INVALID_OPERATION; create* return NON-NULL objects with NO error; is* on such objects returns false. `getError()` while lost: FIRST call per loss epoch returns CONTEXT_LOST_WEBGL, subsequent calls drain normally. The extension singleton cache is untouched by the lost path; `doRestore` re-creates non-WEBGL_lose_context singletons while WEBGL_lose_context keeps identity.
- **RGB8 color attachment on WebGL2** → COMPLETE for BOTH texture and renderbuffer attachments (GLES3 Table 3.13; rgb-format-support.html + framebuffer-render-to-layer.html hard-require COMPLETE for RGB8 textures — the earlier objective-mandated FRAMEBUFFER_UNSUPPORTED deviation was removed in wave-7 because graded CTS pages assert COMPLETE). Unsized RGBA → COMPLETE; unsized RGB texture → COMPLETE (invalidate-framebuffer.html hard-requires it; unsized RGB renderbuffers cannot exist — renderbufferStorage(RGB) → INVALID_ENUM). Format/attachment-point mismatch → FRAMEBUFFER_INCOMPLETE_ATTACHMENT (CTS hard-asserts).
- **ImageBitmap uploads via hidden native-WebGL readback** (teximage.ts `readImageBitmapPixels`, wave-7): the canvas decode round trip (drawImage→getImageData in present/) destroys the RGB of fully-transparent (α=0) texels and loses the bitmap's storage mode, so image_bitmap_from_* CTS pages (straight `premultiplyAlpha:'none'` sources with an entire α=0 column) cannot pass with pure-JS decoding. The upload path uploads the bitmap into a hidden NATIVE WebGL context (getContext captured at bundle load, before the context-intercept harness patch) and readPixels it back losslessly in the bitmap's OWN storage form (straight for 'none', premultiplied otherwise — per WebGL spec §texImage2D TexImageSource). Singleton context, recursion/context-lost guards, never throws. Fallback: lossy canvas decode + `source.premultiply === false` tag (set by the CTS harness on the bitmap) selects straight — pure-JS canvas APIs fundamentally cannot extract straight α=0 RGB from an ImageBitmap.
- **Depth storage**: Float32Array for ALL DEPTH_COMPONENT_* (mandated by raster contract); depth-stencil surfaces split into `depthData` + `stencilData`.
- **renderbufferStorageMultisample** (api/framebuffers.ts): `rb._samples` (actual pinned field name), samples > MAX_SAMPLES=4 → INVALID_OPERATION, single-sampled storage (software resolve at blitFramebuffer). It validates internalformat/MAX_RENDERBUFFER_SIZE, allocates the actual surface via `allocateRenderbufferSurface` (depth planes filled to 1.0), and invalidates FBO status caches — **`WEBGL_multisampled_render_to_texture.renderbufferStorageMultisampleEXT` (extensions/multisampled.ts) DELEGATES to this core WebGL2 method** (the extension is WebGL2-only), so multisampled depth renderbuffers attached via the extension get a real image; a `rb._surface = null` record-only path (old behavior) made depth attachments resolve to no image → FRAMEBUFFER_INCOMPLETE_ATTACHMENT at draw time and silently no-oped every render-target pass (three.js samples>0 render targets: webgl_mirror Reflector RT, webgl_multisampled_renderbuffers EffectComposer RT). `framebufferTexture2DMultisampleEXT` depth-TEXTURE attaches were never affected (texture levels already allocated).
- **TF capture**: draw-time pre-check — if this draw's capture would overflow a bound TF buffer (cumulative session cursor), the draw generates INVALID_OPERATION and captures NOTHING (GLES 3.0 §2.15.2; too-small-buffers.html PASSES). Unbound TF buffers are skipped per-varying; fully-captured primitives count toward `_primitivesWritten`. TF draw-mode mismatch → INVALID_OPERATION. begin requires linked program + non-empty TF varyings + ≥1 buffer (INTERLEAVED) / per-varying (SEPARATE). useProgram/linkProgram reject while TF active; getBufferSubData/bufferData reject TF-bound buffers; bufferData on TF-bound buffer is legal (no INVALID_OPERATION).
- **Sync objects**: event-loop-deferred signaling — `fenceSync` creates the sync with `_signaled = false` and a one-shot `setTimeout(0)` flips it, so `clientWaitSync(..., 0)` returns TIMEOUT_EXPIRED within the same task and ALREADY_SIGNALED after (CTS sync-webgl-specific.html). `clientWaitSync` timeout>0 → INVALID_OPERATION (MAX_CLIENT_WAIT_TIMEOUT_WEBGL=0).
- **Queries**: availability event-loop-deferred — endQuery sets `_resultAvailable` via a batched `setTimeout(0)` flip; ANY_SAMPLES_PASSED(_CONSERVATIVE)/TRANSFORM_FEEDBACK_PRIMITIVES_WRITTEN targets; occlusion counts REAL samples via the `sampleCountRef` hook (raster increments it per depth-passed sample).
- **drawBuffers state is PER-FRAMEBUFFER** (module WeakMap; spec default [COLOR_ATTACHMENT0, NONE×7], synced into `s.drawBuffers` on bind/delete; gated to WebGL2; W1 WEBGL_draw_buffers extension untouched). Documented deviation: default-FB list is [COLOR_ATTACHMENT0] not [BACK] (draw.ts consumers index `db - COLOR_ATTACHMENT0`; getters maps first non-NONE to BACK). drawBuffers() on the default FB NORMALIZES `[BACK]` → `[COLOR_ATTACHMENT0]` before storing (three.js r185 emits drawBuffers([BACK]) on every FBO→null transition; a raw BACK makes `db - COLOR_ATTACHMENT0` negative and every color write/clear silently drops — 19 flat three.js pages). `[NONE]`/`[]` store as-is; API validation still rejects `[COLOR_ATTACHMENT0]` as INPUT on the default FB (only BACK/NONE/[] legal per WebGL2). The W1 WEBGL_draw_buffers default-FB branch (extensions/draw-buffers.ts) normalizes identically.
- **`getActiveUniformsiv`**: declared in webgl2.ts per class docs, but WebGL2 IDL names it `getActiveUniforms` — implemented under BOTH names.
- **Limits** (in `defaultLimits()`): MAX_TEXTURE_IMAGE_UNITS=16, MAX_COMBINED=32, MAX_DRAW_BUFFERS=8, MAX_COLOR_ATTACHMENTS=8, MAX_SAMPLES=4, UNIFORM_BUFFER_OFFSET_ALIGNMENT=256, MAX_CLIENT_WAIT_TIMEOUT_WEBGL=0, MAX_TEXTURE_SIZE=8192, MAX_CUBE=8192, MAX_3D=2048, MAX_ARRAY_TEXTURE_LAYERS=2048, MAX_VERTEX_ATTRIBS=16, MAX_VARYING_VECTORS=64, ALIASED_POINT_SIZE_RANGE=[1,1024], ALIASED_LINE_WIDTH_RANGE=[1,1], MAX_TEXTURE_MAX_ANISOTROPY_EXT=16, MAX_COMBINED_*_UNIFORM_COMPONENTS=262144.
- **Extension status** (registry is the source of truth): 'implement' — ANGLE_instanced_arrays, EXT_blend_minmax, EXT_frag_depth, EXT_shader_texture_lod, EXT_sRGB, OES_element_index_uint, OES_fbo_render_mipmap, OES_standard_derivatives, OES_texture_float(+_linear), OES_texture_half_float(+_linear), OES_vertex_array_object, WEBGL_depth_texture, WEBGL_draw_buffers, WEBGL_blend_func_extended, WEBGL_lose_context, WEBGL_debug_renderer_info, WEBGL_debug_shaders, EXT_texture_filter_anisotropic (aliases WEBKIT_/MOZ_), EXT_clip_control, EXT_color_buffer_float, EXT_color_buffer_half_float, EXT_float_blend, EXT_texture_norm16, KHR_parallel_shader_compile, OES_draw_buffers_indexed, WEBGL_clip_cull_distance, WEBGL_multi_draw, WEBGL_draw_instanced_base_vertex_base_instance, WEBGL_multi_draw_instanced_base_vertex_base_instance (factories in `extensions/base-vertex-base-instance.ts`; methods live on the EXTENSION OBJECT per extension.xml IDL; both delegate to the draw engine with baseVertex/baseInstance in DrawRequest; requesting either IMPLICITLY enables WEBGL_multi_draw), WEBGL_multisampled_render_to_texture, WEBGL_render_shared_exponent, WEBGL_compressed_texture_etc/_etc1 (W2, constants-only). 'null' (getExtension → null; legal per CTS): all other compressed formats (s3tc, s3tc_srgb, astc, pvrtc, bptc, rgtc — texImage2D with their internalformats → INVALID_ENUM), EXT_disjoint_timer_query(+webgl2), EXT_depth_clamp, EXT_polygon_offset_clamp, WEBGL_polygon_mode, EXT_texture_mirror_clamp_to_edge, OVR_multiview2, EXT_render_snorm. Core-promoted WebGL1 extensions NOT exposed on WebGL2 (versions:[1]); EXT_disjoint_timer_query NOT advertised on WebGL2 (CTS checks).
- **Drawing-buffer lifecycle**: WeakMap canvas registry; one context per (canvas, type-slot); conflicting getContext → null. `preserveDrawingBuffer:false` is a hint — buffer persists so screenshots see the last frame. Context constructor allocates `_defaultFB` (via raster/formats when available) + `_presentSurface` (present/createCanvasSurface); after each draw/clear touching the default framebuffer, `presentSurface.present()` is called.
- **preserve:false frame-boundary clear (draw.ts `schedulePreserveClear`)**: the internal drawing buffer is zero-filled at the next frame boundary (rAF / setImmediate / microtask / setTimeout; coalesced to one pending callback) for readPixels-after-composite spec compliance, gated to connected DOM canvases + OffscreenCanvas (detached DOM canvases are never composited so their content survives — CTS buffer-offscreen-test). The 2D-canvas re-present of the cleared buffer runs **WebGL1 only** (`ctx._version !== 2`): WebGL1 needs it for CTS context-attribute-preserve-drawing-buffer.html (drawImage(webglCanvas) after composite must read (0,0,0,255)); WebGL2 skips it — the canvas bitmap retains the last composited frame (native display-retention parity; no graded WebGL2 CTS page reads the canvas bitmap after composite). OffscreenCanvas is never re-presented in either version (its native bitmap is the source for texImage2D/createImageBitmap — webgl_canvas/* upload plain OffscreenCanvas sources with default preserve:false).
- **FBO attachment level rules** (GLES 3.0 §4.4.5/§3.8.10/§3.8.13; immutable-tex-render-feedback + copy-texture-image-same-texture PASS): immutable textures (texStorage*) require only that the attached level's image exists — the [level_base, q] range + mipmap-complete rules are skipped for `tex._immutable`. For mutable textures: q = min(floor(log2(maxSize)) + level_base, level_max) — SIZE-derived (level-0 dims), NOT highest-defined-level; the range check applies even when attached level == base level; the mipmap-complete loop over [baseLevel, q] enforces per-level dims `max(1, baseW >> (l-baseLevel))` + effective-format consistency via `storageFormatKey()` normalization. `resolveAttachmentSurface` resolves non-cube 2D_ARRAY/3D attachments by `entry.layer` (layer N must NOT resolve to layer 0 — tex-unpack-params-imagedata 3D slices).
- **WebGL2 unpack-param validation** (api/teximage.ts `validatePixelsSize`, tex-unpack-params* PASS): INVALID_OPERATION when UNPACK_SKIP_PIXELS+width > DataStoreWidth (ROW_LENGTH?ROW_LENGTH:width) and (3D entrypoints) UNPACK_SKIP_ROWS+height > DataStoreHeight (IMAGE_HEIGHT?IMAGE_HEIGHT:height) — not applied for null srcData. Required size: 2D = skipPixels*bpp + skipRows*rowBytes + (height-1)*rowBytes + width*bpp (last row unpadded, `width` not `rowLength`); 3D adds (skipImages + depth-1)*imageHeight*rowBytes. 2D-vs-3D is decided by ENTRYPOINT (is3D flag), not `depth` (both call sites pass depth=1). texImage3D/texSubImage3D with non-null client ArrayBufferView reject UNPACK_FLIP_Y/PREMULTIPLY_ALPHA (INVALID_OPERATION). pixelStorei boolean unpack params accept ANY truthy value (WebIDL GLboolean — pixelStorei(UNPACK_PREMULTIPLY_ALPHA_WEBGL, 6) is legal). Engine: 2D uploads ignore UNPACK_IMAGE_HEIGHT/SKIP_IMAGES (entrypoint-target discrimination in copyPixelsIntoLevel).
- **texSubImage2D/3D WebGL2 buffer paths validate the view's element type** (w2TypeMatchesView → INVALID_OPERATION; tex-new-formats PASS) — same as the texImage2D path; catches same-length wrong-type views (Float32Array where Uint8Array required).
- **W1 float-texture filterability**: float/half-float textures with LINEAR or any mipmap-LINEAR filter are INCOMPLETE (sample black) unless OES_texture_float_linear / OES_texture_half_float_linear is enabled — `updateCompleteness` via `floatLinearExtensionState(ctx)` (cache read, no self-enable); W2 float filterability is a separate GLES3 rule, untouched.
- **W1 compressed null data**: compressedTexImage2D/compressedTexSubImage2D `data` is NON-NULLABLE in WebGL1 IDL — null/undefined throws TypeError BEFORE GL validation (webgl-compressed-texture-etc PASS); WebGL2 keeps the null-legal path.
- **generateMipmap sRGB invariant (teximage.ts, wave-11)**: for sRGB internal formats (SRGB8_ALPHA8, SRGB8, SRGB_ALPHA_EXT/SRGB_EXT) the 2×2 box filter decodes each texel sRGB→linear, averages in linear space, re-encodes before storing — mip levels hold ENCODED values (the sampler decodes at sampling time; GLES 3.0 §3.8.14). Alpha is never transformed. Non-sRGB formats keep the raw average. tex-srgb-mipmap.html 4P/11F → 5P/0F. The Babylon brightness residuals are NOT sRGB-related: those scenes upload ZERO sRGB internal formats (0 of 152/73/85 texImage2D calls; Babylon does sRGB shader-side via gammaSpace, never GL sRGB formats) — their root causes were found elsewhere: pre-blend fragment clamp (raster, a18b9f8) + Euclidean-norm texture footprint (raster, ca40477); the remaining visual-suite residual family is documented in src/raster/CONTEXT.md.
- **Copy engine (teximage.ts, copy-tex-image* PASS)**: copyTexSubImage writes directly into the destination level at (xoffset,yoffset) with bounds-skip — dest texels outside source-rect∩FB stay UNCHANGED (no zero-filled temp blit); cube copyTexImage keeps the freshly allocated face view (`data[f] = f === face ? freshView : existing?.data[f]`); copyFromReadSurface format-fills the destination channel layout before pack (LUMINANCE_ALPHA [L,A]=[r,a], ALPHA A→r, LUMINANCE L,L,L,1); per-level `TextureLevel.format` key drives surface resolution (the texture-global internalFormat can be overwritten by same-texture copyTexImage2D). copyTex* read-framebuffer validation (wave-11): incomplete → INVALID_FRAMEBUFFER_OPERATION; READ_BUFFER NONE or missing attachment point → INVALID_OPERATION (GLES 3.0 §3.8.5; W1 read point = COLOR_ATTACHMENT0).
- **Float readback gates**: `floatStorageReadOK` accepts OES_texture_half_float alone (implicitly enables EXT_color_buffer_half_float when supported, per CTS), plus OES_texture_float / EXT_color_buffer_half_float (ext-color-buffer-half-float PASS).
- **`sourceDims()` recognizes the VideoFrame duck-type** (string `format` + numeric `displayWidth`/`displayHeight`) for texImage2D/texSubImage2D DOM uploads (image-decoder-to-texture PASS). `srcComponents()` maps SRGB_EXT→3 / SRGB_ALPHA_EXT→4 (texture-srgb-upload PASS).

## Cross-Agent Contract Notes (IMPORTANT for glsl/raster/present agents)
- **Clip/cull distance record transport (CROSS-AGENT, coordinated numbers)**: the vertex record header is **21 floats** — `[x,y,z,w (0-3), pointSize (4), clipDistance[8] (5-12), cullDistance[8] (13-20)]`, varyings start at offset **21**. **Landed end-to-end on all three sides** (gl/draw.ts local `RECORD_OFFSET_CLIP_DISTANCE = 5`/`RECORD_OFFSET_CULL_DISTANCE = 13`/`RECORD_TOTAL_HEADER_FLOATS = 21` == `src/raster/types.ts` `RECORD_HEADER_FLOATS`/`VARYINGS_OFFSET` = 21 — keep them in lockstep). Per draw, `sc.outClipDistance`/`sc.outCullDistance` (Float32Array(8)) are zeroed UNCONDITIONALLY (zero = inside) and written into slots 5-20 of every vertex record; the vctx carries them as `out.clipDistance`/`out.cullDistance` (typed via a local intersection). glsl `leafWrite`/`leafRead` write/read the slots; raster interpolates slots 5-12 (clip) / 13-20 (cull) per-primitive and applies clip/cull semantics (gated on `DrawCall.clipDistPlanes`, wired by `buildDrawCall`). webgl-clip-cull-distance.html 267P/0F.
- **Vertex exec ctx carries `tex` (draw.ts → glsl)**: `executeDraw` builds the vctx with `tex: createTextureEnv(env.bindings)` (same per-draw TextureEnv the rasterizer builds for fragments) — GLSL ES allows texture access in VERTEX shaders and glsl codegen emits `ctx.tex.*` calls there too (three.js morph/skinning texelFetch; without it vertex sampling threw TypeError → blank pages). `VertexExecCtx` in glsl/program.ts deliberately does NOT declare `tex` (glsl selftest stubs provide their own); draw.ts uses the intersection type `VertexExecCtx & { tex: TextureEnv }`.
- **Default VAO identity (lifecycle)**: `initContextResources` aliases `ctx._state.vao = ctx._defaultVAO` — the ACTIVE VAO must BE the persistent default VAO object, never a duplicate (`createDefaultState()` makes its own). Frameworks cache the default VAO's element-array-buffer binding by object identity (Babylon.js); a duplicated state.vao with null EAB → skipped EAB rebind → silent INVALID_OPERATION → black frames.
- **Explicit-dims DOM uploads never scale (teximage.ts → glsl/raster)**: `copyPixelsIntoLevel`'s DOM branch scales the source ONLY for inferred-dims forms (`explicitDims` flag false; SVG width/height attrs). WebGL2 9-arg texImage2D/texSubImage2D + 10/11-arg 3D forms pass `explicitDims = true`: width/height select a sub-rectangle at (UNPACK_SKIP_PIXELS, UNPACK_SKIP_ROWS) of the ORIGINAL source (spec §3.7.2) — scaling before the crop corrupts the rect (conformance2 textures video/image pages).
- **Attrib/instancing convention (draw.ts → glsl)**: the engine fills `ctx.attribs[loc]` with DENSE pools (one pool per bound buffer, laid out consecutively) and `ctx.attribIndices[loc]` = 0-based vertex position for divisor-0 attribs, `floor(instanceId/divisor)` for instanced. glsl codegen MUST read `attribs[loc][attribIndices[loc] * components + c]` — NOT `attribs[loc][vertexId*components+c]`.
- **Occlusion hook (draw.ts → raster)**: draw.ts attaches `(dc as any).sampleCountRef = { value: 0 }` before `rasterizer.draw` and sums `sampleCountRef.value` into the active query's `_result` after. Raster increments `sampleCountRef.value` per depth-passed sample when the field is present (fragment-ops.ts). DrawCall.textures field EXISTS (per-texture-unit `TextureImage`); `dc.fb` comes from `resolveFramebufferTarget` (real now).
- **Uniform store (gl → glsl)**: `ProgramModel.uniforms[].location` is a FLOAT index into the program's float store. `program._uniformStore = new DataView(floatStore.buffer, floatStore.byteOffset, floatStore.byteLength)` aliases glsl's `floatStore`; float writes: byte = `(location + slotOffset + comp) * 4`; int/uint/bool/sampler writes: index `location + slotOffset + comp` into glsl's `intStore` (uint via `>>>0`, bool 0/1, int `|0`). `elementSlots()` = float stride (scalar/sampler 1, vector 4, matrix cols*4). NOTE: glsl's `Program.uniformMap` values are SEPARATE instances from `uniforms[]` entries — gl resolves locations BY NAME (`pm.uniforms.find(x => x.name === ...)` with `[0]`-normalized fallback); do not reintroduce identity `indexOf` bridging. Matrix addressing is float-index (no `*16`).
- **readPixels row order (gl → raster)**: NO y-flip — raster Surface row 0 = BOTTOM (readPixels(0,0,w,h) returns row 0 first). Default FB: RGBA8/UNSIGNED_BYTE only; W2 same. Pack alignment/skip algorithms implemented in draw.ts.
- **Texture image model (gl → raster)**: `WebGLTexture._image: GLTextureImage` = raster `TextureImage` with `levels[{width,height,depth,data:ArrayBufferView[],stencilData?}]`; cube textures = 6 views per level (+X..-Z order, `faceIndex = face - 0x8515`); 3D/2D_ARRAY levels = one view per layer (`data[z]`, matching the raster sampler's `readTexel`), stencilData flat w×h×d. gl allocates levels via raster formats when available, local format table otherwise. DOM-source uploads (texImage2D/3D, texSubImage2D/3D incl. the explicit-dims 3D overloads) decode to normalized RGBA8 and convert in the source domain (`copyPixelsIntoLevel` DOM branch: `domain = isInteger ? 2 : 0`, ÷255 for float destinations).
- **NEAREST_MIPMAP_LINEAR = 0x2702** (WebGL convention, swapped vs GLES) — raster sampler must interpret filter enums per this convention.
- **TF binding model (gl internal — per updated Khronos spec)**: the indexed bindings (TRANSFORM_FEEDBACK_BUFFER_BINDING[i]) are PER-TF-OBJECT state — `bindBufferBase/Range` must write into the bound `WebGLTransformFeedback._buffers[i]`/`_bufferRanges[i]` and persist there (switching-objects.html PASSES); the generic binding point (`bindBuffer(TRANSFORM_FEEDBACK_BUFFER)`) is GLOBAL context state and `getParameter(TRANSFORM_FEEDBACK_BUFFER_BINDING)` must read that global slot. TRANSFORM_FEEDBACK_ACTIVE/PAUSED getters read the bound TF object; the default TF object lives in a WeakMap and is only exposed in `state.transformFeedback` during an active default-TF session so the draw engine captures into it.
- **Lost/restore lives in `lost.ts`** (cycle-free). Do NOT import lifecycle.ts from extensions/misc.ts (module cycle).
- **Compressed textures**: WEBGL_compressed_texture_etc/_etc1 are 'implement' (constants-only, W2); all other compressed internalformats → INVALID_ENUM (all other compressed extensions 'null') — keep it that way until a compressed format is actually implemented.
- **TF capture = RAW bit copy (draw.ts → glsl)**: `captureTransformFeedback`'s integral branch bit-reinterprets the record cells (`new Uint32Array(records.buffer, records.byteOffset + recOff*4, c)` → `dst[j] = recU32[j]`; the store's ToInt32/ToUint32 wrap preserves the bits for both signed and unsigned destinations) — NEVER float→int convert. glsl packs integral varying 32-bit BIT PATTERNS into the record via R.u2f (both int and uint families). A denormal bit-pattern cell converts to 0 under float→int (get-buffer-sub-data-validity.html 27P/0F).
- **R32I fragment-output transport (glsl+raster-owned — fully landed)**: glsl writes int/uint fragment outputs as R.u2f BIT PATTERNS into `ctx.out.color[L][c]` (writeBitKinds marks FRAGMENT-stage outputs of integral type — a VALUE write would fround away |v| > 2²⁴), and raster encodes integer surfaces (`info.isInteger`) by bit-reinterpreting the cell (f32→u32/i32 in `writeColor`/`writeIntColor`, bpe wraps per GLES 3.0 §4.1.7) instead of clamping. gl validates output-family↔attachment type per draw. vertex-id.html 69P/0F; framebuffer-render-to-layer.html 1362P/0F.

## Known Issues / Gaps
- **HALF_FLOAT / 2_10_10_10_REV vertex attribute fetch gap (draw.ts `readFloatComponent`, L1009-1020)**: the float-path decode switch has NO cases for HALF_FLOAT (0x140b), INT_2_10_10_10_REV, or UNSIGNED_INT_2_10_10_10_REV → those attributes fetch as 0.0 (default: `return 0`). vertexAttribPointer validation accepts them (api/vertex-attrib.ts:87-89) but the draw path never decodes them. No graded CTS page or curated three.js/Babylon scene currently exercises these attrib types (they would fail otherwise) — functional gap, not precision. HALF_FLOAT decode exists only in texture-upload (teximage.ts) and readPixels pack (draw.ts:2496) paths.
