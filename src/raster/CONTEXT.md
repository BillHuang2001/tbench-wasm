# src/raster/ — Rasterization Core

## Intent
Pure-JS software rasterization for WebGL 1.0/2.0 (no GPU, zero deps, no per-fragment allocation): consumes post-VS packed vertex records from `gl/` (contract §2 of `../CONTEXT.md`), does primitive assembly, homogeneous clipping, viewport transform, triangle/line/point rasterization with perspective-correct varying interpolation, fragment shader execution in 2×2 quads (derivatives), and fragment ops (scissor/sample-coverage/stencil/depth/blend/dither/sRGB/colorMask). Also owns the SINGLE shared pixel-format registry (`formats.ts`) and the texture sampler (`sampler.ts`) used by `gl/` and `glsl/` (contract §3). Leaf module: imports nothing from `gl/` or `glsl/` at runtime.

## API Surface (public contract — pinned; do not rename)
- `draw(dc: DrawCall): void` (index.ts) — the rasterizer entry. `DrawCall` (types.ts) keeps every field from contract §2 (mode/count/first/instanceCount/vertices/vertexStride/program/varyingsOffset/fb/viewport/depthRange/scissor/cull/polygonOffset/dither/colorMask/blend/depthTest/depthMask/stencilTest/sampleCoverage/rasterizerDiscard/lineWidth) plus: `textures` (per-unit `{img, state}` effective bindings) and `drawBuffers` (output location → color attachment index or −1 for NONE).
- DrawCall carries three fields beyond contract §2's list: `uniforms` (fragment uniform store), `uniformBlocks?` (WebGL2 UBO stores), `sampleCountRef?` (occlusion counter — see below).
- Vertex record layout (types.ts): `[x, y, z, w, pointSize, clipDist[8], cullDist[8], varyings...]` with `VARYINGS_OFFSET = RECORD_HEADER_FLOATS = 21`, `RECORD_OFFSET_CLIP_DISTANCE = 5`, `RECORD_OFFSET_CULL_DISTANCE = 13` (8 clip + 8 cull distance floats per vertex — WEBGL/EXT_clip_cull_distance; gl/ zeroes the 16 slots per draw, so unwritten = 0). Pre-viewport: x/y/z/w = clip space. Post-`applyViewportTransform`: x/y/z = window coords, **w preserved as clip w** (perspective + gl_FragCoord.w). `computeVertexStride(varyings)`, `writeVertexHeader(...)` helpers. Instanced addressing: instance i, vertex j → record `first + i*count + j` (gl/ packs all instances contiguously).
- `FragmentExecCtx` (types.ts) — the FULL `BaseExecCtx` set (uniforms = default-block float store, intUniforms = default-block int/uint/bool/sampler store, blockStores/blockIntStores = uniform-block data INDEXED BY BLOCK INDEX — raster converts the DrawCall's name-keyed `uniformBlocks` into index-keyed arrays, zero-filled when unbound; textures = per-unit images or null; samplerStates = effective per-unit state or DEFAULT_STATE; scratch/intScratch = codegen locals sized from program.scratchSize/intScratchSize) plus varyings `{v, ddx?, ddy?}`, fragCoord, frontFacing, pointCoord, out.color[loc] + out.secondary?[loc] (dual-source index-1 colors — see below), out.fragDepth, `discarded: boolean` (codegen sets on `discard`; raster resets before each invocation) and `tex: TextureEnv` (texture sampling — see below). glsl codegen compiles against this exact shape.
- `TextureEnv` (types.ts) — codegen-facing sampler: `units[unit] = {img, state}`; methods `sample2D/sample2DLod/sample3D/sample3DLod/sampleCube/sampleCubeLod/sample2DArray/sample2DArrayLod/sample2DShadow/sampleCubeShadow/sample2DArrayShadow/texelFetch2D/texelFetch3D/texelFetch2DArray` (unit, coords, explicit ∂/∂x ∂/∂y, bias or lod). All write into shared scratch `out` (float) + `outInt`/`outUint` (raw bits, same buffer). No allocation.

### Integer color buffers — fragment-output BIT-REINTERPRETATION (writeColor)
`FragmentOpsImpl.writeColor` routes `tgt.info.isInteger` targets to `writeIntColor` BEFORE any blend/sRGB/value-clamp: each output component's float32 bit pattern (the glsl codegen `u2f` transport — contract (a) of the R32I precision contract) is stored RAW per GLES 3.0 §4.1.7 wrap semantics — bpe=4 → full 32 bits, bpe=2 → low 16, bpe=1 → low 8 (signed/unsigned storage share the same bits); RGB10_A2UI (packed u32, detected as `bytesPerPixel !== components·bpe`) packs per-component 10/10/10/2-bit fields from the 32-bit patterns. colorMask RMW is BIT-based (masked channels keep their CURRENT STORED BITS via formats.ts `readIntBits`/`readU32At` — never the value decode). Blend is skipped (GLES 3.0 §4.1.7: no blending for integer buffers; gl/ does NOT gate BLEND itself — the raster gate is the only enforcement). sRGB n/a. CLEAR (`clearColorSurface` via `info.encode`) and BLIT (`blitColorSurface` decode→encode) stay VALUE-based — untouched by this path. Transport: glsl writes int/uint fragment outputs as `u2f` bit patterns (writeBitKinds marks FRAGMENT-stage outputs of integral type); raster bit-reinterprets the cells (see Known Issues).

### Dual-source blending (WEBGL_blend_func_extended) — raster side
- Blend-factor tables in fragment-ops.ts implement the four SRC1 factors (gl-enums.ts): `SRC1_COLOR` (0x88F9) / `ONE_MINUS_SRC1_COLOR` (0x88FA) / `SRC1_ALPHA` (0x8589) / `ONE_MINUS_SRC1_ALPHA` (0x88FB) per GLES 3.0 table 4.2: the RGB equation uses the SECONDARY color's channel (SRC1_COLOR) or alpha (SRC1_ALPHA); the alpha equation uses the secondary's ALPHA for every SRC1_* factor.
- The secondary color = the fragment output with blend index 1 (gl_SecondaryFragColorEXT / `layout(index=1)`). Raster allocates `ctx.out.secondary` (parallel to `ctx.out.color`, reset to (0,0,0,1) per invocation) and `FragmentOps.finalize`/`writeColor` pass `secondary[L]` into `blendColor` as the `src1` param (absent → SRC1_* factors yield 0).

### Occlusion queries (`sampleCountRef` — WebGL2 SAMPLES_PASSED)
`DrawCall.sampleCountRef` is an optional out-param `{ value: number }` owned by gl/. The fragment pipeline increments it exactly once per sample that passes the stencil AND depth tests (i.e. every fragment that reaches the blending stage):
- Shaders NOT writing gl_FragDepth: incremented in `FragmentOpsImpl.test()` immediately after the depth-read test passes (before the fragment shader runs).
- Shaders writing gl_FragDepth: the depth test is deferred to `finalize()` (post-shader), so the increment happens there after the post-shader depth test passes.
- Shader-`discard`ed fragments ARE counted when the depth test already passed in test() (the count happens before the shader); for gl_FragDepth shaders a discarded fragment never reaches finalize() and is not counted.
- Helper invocations (outside-pixel quad lanes that exist only to provide derivatives) never count — runQuad only calls ops.test for inside pixels.
- `rasterizerDiscard` draws return before any fragment work: nothing is counted.
- Blending/dither/sRGB/colorMask never affect the counter. The counter is per-sample; the current rasterizer is single-sample (each fragment = 1 sample).
- `sampleTexture(img, state, coord: SampleCoord, bias, out)` + `sampleTextureLod` + `sampleTextureShadow` + `texelFetch` (sampler.ts) — generic core; `SampleCoord = {v, dx?, dy?}` (dx/dy optional; zero-filled scratch when unused).
- `formats.ts` — `getFormat`, `defineFormat`, predicates (`isColorFormat` etc.), `isValidRenderbufferFormat(f, 1|2)`, `isValidTextureInternalFormat`, `getTexImageConverter(srcFmt, srcType, dstFmt)`, `getPackConverter(intFmt, packFmt, packType)`, `halfToFloat/floatToHalf/sRGBToLinear/linearToSRGB/packDepth24Stencil/unpackDepth24`, plus the raw integer-cell accessors `readIntBits(data, off, bpe)` / `writeIntBits(data, off, bpe, bits)` (low `8·bpe` bits wrap; used ONLY by the shader-output integer write path — clear/blit keep value `encode`). Registry populated at module init via `defineFormat()` for every entry in `ALL_INTERNAL_FORMATS` (WebGL1 unsized formats get concrete sized storage entries under their own GLenum keys).
- `surface.ts` — `createSurface`, `getDepthData`, `getStencilData`, predicates.
- `fragment-ops.ts` — `FragmentOpsImpl` (implements `FragmentOps`), `runQuad(rs, qx, qy, inside)`, clear/blit helpers, `blendColor` (exported for unit tests).
- `clip.ts` — `clipPrimitive` (6 planes, interpolates all fields linearly in clip space), `pointIsVisible`, `applyViewportTransform`, `MAX_CLIPPED_VERTICES = 7`.
- `triangles.ts`/`lines.ts`/`points.ts` — `rasterizeTriangle(buf, i0, i1, i2, stride, rs)`, `rasterizeLine`, `rasterizePoint` (one primitive per call, window-space records).
- Impl limits (types.ts): `ALIASED_POINT_SIZE_RANGE = [1, 1024]`, `ALIASED_LINE_WIDTH_RANGE = [1, 1]` — gl/ MUST import these for getParameter (single source of truth).
- `gl-enums.ts` — the GL constants raster interprets (values spec-fixed; gl/ keeps its own larger table).

## Constraints
- Zero runtime deps; no per-fragment allocation anywhere (all scratch in `RasterState`/caller `out` arrays; quad buffers allocated once per draw).
- Each file ≤ ~1000 lines. Split by responsibility (current layout already does).
- **Surface rows: row 0 = BOTTOM** (GL window coords, y up). present/ flips for display; readPixels does NOT flip. Texture rows: row 0 = bottom too (upload flip is gl/'s concern).
- GL error queue is gl/'s domain — raster never throws to the page; internal exceptions must be caught by gl/ at the API boundary.
- Raster's program view (`RasterProgram` in types.ts) is a STRUCTURAL subset of glsl's `Program` — glsl must ensure its Program is assignable (import the type from `../raster`); `VaryingInfo` is owned here, glsl imports it.

## Design Decisions
- **2×2 quads (MANDATORY when `usesDerivatives`)**: fragment shader always evaluates in 2×2 quads; outside pixels are helper invocations (shader runs, outputs discarded) so inside pixels get correct ddx/ddy (differences across the quad) — matches the parent design decision and makes derivatives work for both dFdx and implicit-LOD texture(). Fast per-pixel path (runFragment) allowed only when `!usesDerivatives` (spec-correct; helpers are semantically irrelevant then).
- **Flat varyings**: provoking vertex = LAST vertex of the primitive (GLES). rasterizer copies provoking values into ALL vertices BEFORE clipping so clip's linear interpolation is harmless. Integer varyings are flat; their bits travel in float records (codegen reinterprets via Int32Array views).
- **Two-phase fragment ops**: `test()` (scissor → coverage → stencil test → depth READ) runs before shading; `finalize()` (depth write + stencil zpass + blend + sRGB + mask + write) runs after, so `discard` suppresses ALL writes and gl_FragDepth shaders get a post-shader depth test.
- **Depth/stencil storage**: DEPTH_COMPONENT* → Float32Array (even 16/24-bit); DEPTH*_STENCIL* → split planes (Float32 depth + Uint8 stencil); packed form only materializes at readPixels via `getPackConverter`. All float formats stored as Float32Array (16F/R11F/RGB9_E5 included); packed GL forms exist only at upload/readPixels boundaries.
- **Polygon offset**: per-fragment offset = m·factor + r·units, m = max(|dz/dx|,|dz/dy|) (constant per triangle), r = 2^-24. Triangles only.
- **Dither**: the DITHER state is accepted (gl.enable/getParameter) but the algorithm is a NO-OP — the spec leaves it implementation-defined, and all shipping implementations (ANGLE, SwiftShader, native drivers) do not dither; CTS exact-value readbacks (e.g. EXT_texture_norm16) expect plain round-to-nearest, so any position-dependent dither breaks them. **Sample coverage** (single-sample): deterministic per-fragment hash threshold ≈ value (invert flips); documented approximation — refine against CTS `sample-coverage` if it fails.
- **sRGB**: sampler decodes sRGB texels to linear; blending on SRGB8_ALPHA8 targets happens in linear space (decode dst → blend → re-encode).
- **Lines**: diamond-exit rule for width 1 (critical for three.js wireframe screenshots vs GPU references); width > 1 approximated as quads (must not crash).
- **Points**: squares; size clamped to ALIASED_POINT_SIZE_RANGE at rasterization; pointCoord = (pixelCenter − (center − s/2))/s; half-open coverage so a size-1 point at an integer center still covers its pixel.
- **Unwritten fragment outputs** treated as (0,0,0,1) (spec leaves undefined; ANGLE-compatible choice). The dual-source SECONDARY output follows the same convention (raster resets `ctx.out.secondary` to (0,0,0,1) per invocation).
- **Texture LOD**: λ = log₂(max ρx, ρy), ρx = sqrt((∂u/∂x·w)² + (∂v/∂x·h)²) — the GLES 3.0 §3.8.14 Euclidean-norm footprint (z term joins in for 3D); clamp to [minLod, maxLod] + bias; mip filter selects level(s). Anisotropy: ρ_aniso = max(ρx,ρy)/min(aniso, max(ρx,ρy)/min(ρx,ρy)), then N-tap filtering (see the next bullet). Incomplete textures → (0,0,0,1). Cube maps seamless. **Cube LOD uses face-mapped (s,t) derivatives via the shared face-selection helper (`faceMap`/`cubeRho`) — magnitude-invariant; matches deqp's `computeCubeLodBoundsFromDerivates` (chain rule through |ma| incl. the |∂r_m/∂x| correction term).**
- **N-tap anisotropic filtering (sampler-aniso.ts)**: when the EXT gate is active (maxAniso > 1, TEXTURE_2D, mipmap min filter, λ > 0) the single bilinear tap is replaced by N = pow2ceil(min(ceil(ρmax/ρmin), maxAniso)) equally-weighted bilinear taps along the MAJOR footprint axis (u when ρx ≥ ρy, else v), at UV offsets ((i+0.5)/N − 0.5)·2^λ/size₀ (level-λ texel units centered on the sample UV — the EXT spec's "equally spaced samples in texture space at LOD Lamda" form with the symmetric (i+0.5)/N convention hardware uses; the spec's literal i/(N+1)−1/2 spacing is an errata-quality artifact). Trilinear (LINEAR_MIPMAP_LINEAR) blends the SAME level pair with the SAME f for every tap; shadow samplers compare per tap (readTap); explicit LOD (textureLod) bypasses AF (the spec defines N from pixel-footprint derivatives, which an explicit LOD has none of — ANGLE/hardware behavior); the u8 fast path stays exact (filter2DU8Tap per tap). Isotropic footprints (ρx==ρy → N=1) and magnification (λ ≤ 0) never tap — bit-identical to the pre-AF single-tap path. Zero allocation: tap params ride module scratch (anisoTapParams), accumulation in module buffers.
- **formats decode/encode take an `out` param** (deviation from the illustrative `→ [r,g,b,a]` in contract §3 — required by the no-allocation rule). Decode is a correctness path only; the sampler reads raw typed arrays with format-class fast paths.

## Known Issues / Gotchas
- **Clip/cull-distance consumption (landed end-to-end)**: raster consumes WEBGL/EXT_clip_cull_distance per the 21-float header record layout (`RECORD_OFFSET_CLIP_DISTANCE = 5`, `RECORD_OFFSET_CULL_DISTANCE = 13`, `VARYINGS_OFFSET = RECORD_HEADER_FLOATS = 21`); gl/ writes the same 21-float headers in lockstep (its local `RECORD_TOTAL_HEADER_FLOATS = 21`; tests/unit record-layout pins updated to the 21-float header, unit tests 148/148). Semantics implemented: CULL is value-driven with NO enable (EXT_clip_cull_distance: "if the cull distance for any enabled cull half-space is negative for all of the vertices of the primitive, the primitive is discarded" — slot i discards when EVERY vertex has cullDist[i] < 0; unwritten slots are zero → never cull), applied BEFORE clipping (spec order: cull volume first, then clip volume); CLIP is gated on `DrawCall.clipDistPlanes` (bitmask of enabled CLIP_DISTANCE<i>; absent → 0 → byte-identical legacy pipeline), user planes applied AFTER the 6 standard planes with the crossing clip distance linearly interpolated at the same t as position (interpRecord covers the slots); POINTS are discarded (not clipped) when an enabled plane has clipDist < 0, after the existing near/far check; fragment `gl_ClipDistance`/`gl_CullDistance` arrive via `ctx.clipDistance`/`ctx.cullDistance` (length 8, ALWAYS allocated/filled by raster — perspective-correct interpolation like varyings; optional on FragmentExecCtx only for hand-built test ctxs). Clip-buffer sizing: `clipPlanes === 0` keeps the legacy `MAX_CLIPPED_VERTICES` sizes; otherwise both clip buffers are `9 + popcount(planes)` records (S-H bound ≤ 3+P). Pass alternation in clip.ts: with an ODD total pass count (6 + odd popcount) the even/odd scratch↔out-head alternation is SWAPPED so the final pass still reads scratch (an in-place final pass with outBase 0 would alias and corrupt — S-H may write 2 records per input vertex read).
- **Integer fragment-output transport (landed end-to-end)**: raster's bit-reinterpret write path (see API Surface) consumes glsl's `u2f` BIT-PATTERN writes of int/uint fragment outputs (writeBitKinds marks FRAGMENT-stage outputs of integral type) — `conformance2/rendering/vertex-id.html` 69P/0F, `conformance2/rendering/framebuffer-render-to-layer.html` 1362P/0F. Raster path verified end-to-end through draw() (30/30 checks: denormal/NaN/clean-float cells, 8/16/32-bit wraps, RGBA32I, packed RGB10_A2UI fields + field-level colorMask, blend skip).
- **LOD/filtering spec audit (completed)**: derivative spacing is SPEC-OK — `setupFragmentCtx` (fragment-ops.ts) fills ddx/ddy as 1-px quad differences from the quad-anchor slot (ddx = slot1 − slot0, ddy = slot2 − slot0, in [pixel][component] quad layout), IDENTICAL for all 4 lanes (GLSL dFdx/dFdy semantics: the sign must not flip per lane; magnitudes are quad-wide so implicit-LOD |ddx|/|ddy| is unaffected); the quad path is guaranteed for every implicit-LOD texture() (glsl semantics sets `uses.derivatives` for all implicit-LOD names incl. inside user functions), so the fast path can never sample with zero derivatives. Mip selection matches GLES 3.0 §3.8.14 (ρx = sqrt(Σ_i (∂coord_i/∂x·size_i)²) — the Euclidean-norm footprint; the per-axis max form is deqp's MINIMUM-LOD bound and understates ρ by up to √2 for diagonal derivative vectors, yielding λ up to 0.5 levels too fine; bias added before [minLod,maxLod] clamp; round(λ) ≡ ⌊λ+0.5⌋; LINEAR_MIPMAP_LINEAR level0=clamp(⌊λ⌋,base,hi), level1=min(level0+1,hi), f=frac(λ); λ≤0 → mag filter at base). Known deviations (all low-impact for the target visual suites):
  - **Anisotropy LOD (sampler.ts computeLod)**: ρ' = ρ/min(maxAniso, ρ/min(ρx,ρy)) uses the EXACT ratio while the N-tap stage rounds N up (ceil / power-of-two), so for footprint ratios R ∈ (1, 2^k) with R < maxAniso the sampled λ is up to ~1 level HIGHER (blurrier) than a GPU that derives λ from the rounded N — INTENTIONAL: A/B experiments (Babylon Hill Valley/Sponza/The car) proved ±1 level shifts, the rounded-N λ form, and the L1 footprint ALL strictly worse, so λ is pinned to the exact-ratio form. Exact at R = powers of two and R ≥ maxAniso (the Babylon scenes use maxAniso = 4). The N-tap machinery itself (N convention, tap offsets, gating) lives in `sampler-aniso.ts`; see its module header for spec citations.
  - **textureOffset (glsl/codegen/runtime.ts tex*OffsetApprox)**: samples at FIXED LOD 0 instead of the GLSL ES 3.00 §8.8 implicit derivative LOD (semantics still marks it derivatives-using, so the quad path runs but gradients are ignored) — minified textureOffset lookups use the mag filter at base level (over-sharp vs GPU); offset also approximated (u + ox/w), deviating for LINEAR near wrap edges. Unused by Babylon/three.js core shaders.
  - **gl_PointCoord duals are (0,0)** (glsl codegen) → point-sprite texture() with UV = gl_PointCoord gets ρ=0 → λ=minLod → mag filter at base; GPUs compute real pointCoord derivatives (1/size). Affects textured point sprites (Babylon particles) only.
  - Corner nit: ρ uses level-0 dims (img.width/height, maintained only on level-0 upload, teximage.ts) — for TEXTURE_BASE_LEVEL > 0 the footprint scale and the [base,hi] level range are inconsistent by 2^baseLevel (rare in practice).
- **Blit (blitColorSurface) semantics** (GLES 3.0 §4.3.2): same-size rects blit WITHOUT filtering even when LINEAR was requested (as NEAREST — bilinear weights would be exactly 0/1, and the sRGB decode→encode round trip would corrupt bytes a plain copy keeps exact). A destination pixel is written ONLY when its mapped center lies inside the source surface — otherwise it retains its previous value. sRGB sources decode to linear before any filtering; sRGB destinations re-encode the linear result (RGB only; alpha never converts). Negative srcW/srcH/dstW/dstH (flipped/mirrored rects) are legal; zero-size rects are no-ops.
- **Pre-blend fragment-output clamp on fixed-point targets (writeColor, fragment-ops.ts)**: fragment colors are clamped to [0,1] BEFORE blending when the color target is normalized (GLES 3.0 §17.3.7) — branch-free clamp + per-draw scratch arrays (`srcClampScratch`/`src1Scratch`, allocated once per draw), applied to both the primary source and the dual-source secondary (EXT_blend_func_extended), covering MIN/MAX equations too. Float targets (RGBA16F/32F) keep HDR values (blending is legal there). The integer branch returns before blend (GLES 3.0 §4.1.7); the non-blend path is unaffected (encode() clamps anyway). Rationale: native GPUs clamp pre-blend; without it, HDR shader outputs (Babylon PBR glass src = 0.588 + 0.9·specComp + 0.3·refl reaches ~1.2–2.0) blended with α<1 render too bright — probe-verified against native SwiftShader with in-page readPixels (band x∈[0,165], y∈[112,183] of Hill Valley: native == 0.4·clamp(C,0,1) + 0.6·dst EXACTLY, ours-unclamped == 0.4·C + 0.6·dst with C ≈ 255–510+ → +20.7/channel → band +15.55 luma). The 2,071-test CTS gate cannot catch this (every CTS blend test uses in-range src values).
- **Integer attachment at location 0 with BLEND enabled would blend raw ints**: blend must be skipped entirely for integer buffers (GLES 3.0 §4.1.7); the writeColor integer branch returns before the blend stage (and the blend gate carries a defensive `!info.isInteger`).
- Compressed formats (S3TC/ETC/ASTC/PVRTC) are OUT OF SCOPE initially — extension tests skip when getExtension returns null; three.js/Babylon degrade gracefully. Do not block on them.
- deqp exactness tests (lines/points) are optional (not in the 2,071 graded count); the graded CTS line/point tests are tolerant, but three.js wireframes ARE graded by screenshot diff — diamond-exit must be genuinely implemented, not approximated.
- `gl_FragCoord.w` = 1/w_clip (perspective-correct interpolation of 1/w).
- Clipping: triangle results are fan-able polygons (up to 7 verts) — rasterize as fan from vertex 0.
- `dc.varyingsOffset` must equal `VARYINGS_OFFSET` (21) — kept as a field for contract fidelity; draw() should trust it.
- SampleCoord for 2D_ARRAY: v[2] = layer (not filtered/wrapped); shadow 2D: v = [u,v], ref separate.
- FBO multisample renderbuffers: raster draws single-sample surfaces; gl/ resolves via `blitFramebuffer` (blitColorSurface with 'nearest'/'linear').
- Line clip (count==2, clipPrimitive): segment-parameter path — one-inside → 2 verts (inside + intersection), both-inside → 2, same-side fully-outside → 0, degenerate/point-touch → 0, and a segment straddling the volume (both endpoints outside, interior crosses it) → interior segment (2 verts, GLES 2.0 §2.13). Do NOT change straddling to 0 — visible lines would vanish.
- **Large-viewport allocation** (`conformance/rendering/rendering-stencil-large-viewport.html`, WebGL1): resizes the drawing buffer to 32767×32767 ≈ 4.29GB (RGBA8, legal per MAX_VIEWPORT_DIMS); passes (8/8) under the runner's 10-min per-page override, but if a future machine OOMs, cap the surface allocation in `surface.ts` WITHOUT changing the page's assertions (it only checks a few pixels' stencil behavior).
- **Babylon visual-suite residuals (task-5 final; native baselines) — per-texel texture-sampling noise + missing 4×MSAA edges; NO coherent lighting/shadow/tone component**: ours-vs-golden post-fix (pre-blend clamp a18b9f8 + Euclidean-norm footprint ca40477): Sponza 0.0764, The car 0.0684, Hill Valley 0.0307 (budgets 0.011/0.05/0.011), Flat2009 0.0219, Heart 0.0180, Windows cafe 0.0136 (budget 0.011 each). Native SwiftShader vs golden: Sponza 0.0021, The car 0.0090, HV 0.0027 → goldens ARE reproducible natively; the residual is genuinely ours (ours-vs-native ≈ ours-vs-golden). Anatomy (ours vs native, luma, task-5 probes): flat regions perfect (mean|lumaΔ| ≤0.35) → no global color/format/blend/encode issue; channels in lockstep (≥99.8%); per-texel salt-and-pepper in textured regions (Sponza: 16.9k 4-connected components / 19.7k px>8, sign-mixed, no region coherence — sunlit atrium stone; HV: bottom-band foreground field; The car body nearly clean); ALL px>50 tails are missing-AA edge pixels (52-80% edge class; The car's bright-highlight darkening is 96% partial-coverage at highlight edges, NOT a value bug). Mechanisms exhausted by A/B (all worse or scene-trading): global λ bias (±1/±0.5/±0.25), rounded-N aniso λ, aniso taps off, half-texel convention, L1 footprint. Exonerated: shadows (Sponza scene file has zero shadowGenerators — verified), mediump (all 126 shaders highp), dither (compiled out), gamma pow (not live), upload + mip content (bit-exact vs native GPU). Write path verified spec-correct: encode = `Math.round(clamp(v,0,1)·255)` round-to-nearest (GLES 2.0 §2.1.8), sRGB applied exactly once, sampler decode exact, interpolation/viewport float64. Classification: fp32-vs-double interpolation/filter math at texel boundaries (per-texel component) + binary coverage vs native 4×MSAA (edge tails) — the documented precision/AA family; further gains need native-GPU-matching edge rendering or fp32-exact filter emulation (out of scope). Possible future lead (gl-side, NOT raster): Flat2009's mild +0.5..+1.8 LSB brightness in dark/shadow regions — shadow-map depth stored Float32 vs native 16/24-bit quantization (Sponza rules out shadows as the general cause, but Flat2009's lead stands); quantizing depth-texture storage is NOT clearly-correct (CTS-tolerant but golden-match uncertain).
## Test Strategy
- `tests/unit` (vitest, Node): formats (encode/decode round-trips, converters, half/sRGB helpers), sampler (filters, wraps, LOD selection, N-tap anisotropy vs independent reference, shadow compare, texelFetch, integer raw bits), clip (6-plane correctness, interpolation), triangles (top-left rule, perspective interpolation, flat), lines (diamond-exit patterns), fragment ops (blend math incl. sRGB, stencil sequences), rasterizer (draw pipeline end-to-end vs CPU reference).
- Pipeline-level coverage: pipeline-level behavior — triangle fill, diamond-exit lines, blending, stencil, scissor, occlusion counting, instancing — lives in `tests/unit/raster-pipeline.test.ts` and in the CTS/visual suites.
- Primary gate: `tests/conformance` (2,071 CTS tests) — raster correctness is judged there (`rendering/`, `glsl/`, `textures/`, `drawing/`, `state/` groups).
- three.js/Babylon visual suites exercise raster performance (no per-fragment allocation matters — tens of thousands of triangles).

- `gl-enums.ts` → GL constants raster interprets
- `formats.ts` → pixel-format registry + upload/readPixels converters + half/sRGB helpers + raw integer-cell accessors (readIntBits/writeIntBits)
- `sampler.ts` → texture sampling core (LOD, filters, projectToFace) + createTextureEnv; split across `sampler-raw.ts` (raw texel taps), `sampler-env.ts` (codegen-facing env) and `sampler-aniso.ts` (N-tap anisotropic filtering: gate, N convention, tap placement, tap loop — imports only types.ts + gl-enums)
- `surface.ts` → surface creation/view resolution
- `fragment-ops.ts` → FragmentOps (scissor/coverage/stencil/depth/blend/dither/sRGB/mask + integer bit-reinterpret write path), runQuad quad driver, clear + blit helpers
- `clip.ts` → homogeneous clipping + viewport transform
- `triangles.ts` → triangle rasterization (top-left rule, perspective interpolation, polygon offset)
- `lines.ts` → line rasterization (diamond-exit; wide-line quads)
- `points.ts` → point rasterization (size clamp, pointCoord)
- `rasterizer.ts` → draw() driver: assembly, instances, flat fixup, cull, dispatch
- `index.ts` → public API re-exports
